# Review findings and their status

An application review and audit was done on 2026-10-07 against commit `2b0daac` (backend, frontend, infrastructure, tests, docs). It found a design core worth keeping, one blocker on a fresh install, several critical security gaps, and a reliability story that was only partly true in the running system. This file records every finding and what became of it. The original evidence and line-by-line detail are in git history (commit `66d7126`); the findings are numbered `F-01` to `F-33` and the ADRs refer to them by number.

Since then the work was done in four steps: a fresh clone was made to build and run, the security baseline was put in place, the broker-based runtime was replaced by a PostgreSQL job queue (ADR 0017, 0018), and the documents were rewritten to match the code. Everything below was checked against the code and the test suite as of the last of those.

## Still open

Ordered by what I would do next.

1. **Credentials outside connections** (F-19, ADR 0011). Connection credentials are encrypted and write-only now, but a token typed into a step is stored in plaintext in the workflow definition and shown in the UI, secrets that an earlier step puts into the instance data are stored and logged, and `SECRETS_KEY` sits beside the database URL. Flag the inline fields in action schemas as secret (or strip them when a connection is selected), keep secrets out of `instances.data` and the `log` handler's output, and consider a secret manager for the key.
2. **Definition validation** (F-10). Check on save that `start_at`, every `next`, `on_true` and `on_false` exist, that step types are known, and that `connector_id` matches the action; cap the steps one instance may run so a loop through action steps ends.
3. **Webhook de-duplication** (F-18). Store GitHub's delivery id and Slack's event id with a unique constraint so redeliveries do not start a second run; make the trigger route a plain `def`, or acknowledge first.
4. **Lease heartbeat or per-step timeouts** (ADR 0018). A step longer than `JOB_LEASE_SECONDS` (default 300) is run again; extending the lease while a handler is alive would remove that limit. Handlers also lack rate limiting and `Retry-After` handling for third-party APIs.
5. **API hygiene** (F-20). Catch `psycopg2.errors.UniqueViolation` instead of matching the text "unique"; make `create_version` race-safe; validate and bound `limit`, `offset` and `status`; take CORS origins from configuration; use timezone-aware timestamps and set request size limits.
6. **Operational hardening.** Resource limits and a non-root nginx image; pin dependency versions (F-21) and add a Python linter; remove the legacy `initial_step` and `final_step` handlers and the committed `.vscode/settings.json` (F-23); TLS in front of the stack; a worker heartbeat so `/health` can tell an idle worker from a missing one; Prometheus multiprocess mode, a label-safe `endpoint` label and an `X-Request-ID` header (F-15).
7. **Frontend** (F-27 to F-31). A race-safe polling hook that keeps the last good data on error; client-side validation in the builder and consistent `next` links when steps move; stable keys so renaming a step does not lose focus; an error boundary, labels and `aria` attributes; component tests; upgrade `react-router` and `vite` and re-run `npm audit`; URL-encode path segments; do not discard the draft when following the connections link; show connection form errors.
8. **Per-user identity** (ADR 0020). One shared key means no audit trail and no revocation per person; per-user keys or an identity provider are the next step if more than one team uses this.
9. **DNS rebinding and fixed-host connectors** (F-06 residual). Pin the resolved address for the connection or add network egress rules; apply the guard's reasoning to values templated into GitHub and Trello URL paths.

## What was not verified

- The GitHub Actions workflow has never run on GitHub (`npm test` there needs Node 22.18 or newer).
- No real signed delivery from GitHub, Slack or Trello has been tried; Trello's signing scheme follows its documentation.
- There is no TLS, and the stack has not run on a real cloud server. Performance was measured on a pinned laptop core (`docs/scalability.md`).
- `make` is not installed on the machine used, so the Makefile was checked structurally and not run.
- Backup and restore of PostgreSQL were not exercised. Retention was exercised against a real PostgreSQL and on the compose stack, but not with a large backlog of runs.
- The connection form (password inputs, "saved" marker, blank keeps the stored value) has not been looked at in a browser. The API behind it is covered by tests and the smoke test, and the form by lint, type-check and the production build.
